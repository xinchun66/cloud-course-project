\section{华为云实验环境}

本章对课程设计使用的华为云实验环境进行说明。按照任务书要求，本项目主要使用华为云 SWR、CCE、OBS 和 ELB 四类服务：SWR 用于保存后端和前端容器镜像；CCE 用于提供托管 Kubernetes 集群；OBS 用于 Spark 大数据分析场景中的数据存储接口；ELB 用于将后端服务以公网入口暴露给外部访问。环境搭建过程不仅决定后续应用能否部署成功，也直接影响截图验收中关于 Kubernetes 版本、Worker 节点数量、节点状态和公网访问能力等关键评分点。

本项目在华为云华北-北京四区域开展实验，创建 CCE Standard 集群 \texttt{cloud-course-cce}，并配套创建 VPC、子网、Worker 节点和负载均衡资源。为了控制代金券消耗，同时满足任务书中不少于两个 Worker 节点和 Kubernetes 版本不低于 1.27 的要求，集群采用按需计费模式，Worker 节点规格选择 2 vCPU / 4 GiB。环境配置完成后，通过 CloudShell 连接集群并执行 \texttt{kubectl get nodes -o wide}、\texttt{kubectl cluster-info} 和 \texttt{kubectl version --client} 等命令进行验证。

\subsubsection{SWR镜像仓库配置}

SWR 是本项目中连接本地容器构建与云端 Kubernetes 部署的关键环节。后端 Flask 服务和前端 Nginx 服务在本地完成 Docker 镜像构建后，需要推送至华为云 SWR，随后 CCE 节点才能在创建 Pod 时从私有镜像仓库拉取镜像。由于 SWR 镜像仓库通常为私有仓库，后续 Deployment 中还需要结合镜像拉取密钥或 CCE 自动生成的 \texttt{default-secret} 进行鉴权。

\subsubsection{CCE集群配置}

CCE 是第一部分云计算平台搭建的核心服务。项目创建的是 CCE Standard 集群，集群名称为 \texttt{cloud-course-cce}，区域为华北-北京四，Kubernetes 版本为 v1.34，满足任务书中“集群版本不低于 1.27”的要求。网络方面，集群绑定 VPC \texttt{cloud-course-vpc}，网段为 \texttt{192.168.0.0/16}；子网名称为 \texttt{cloud-course-subnet}，网段为 \texttt{192.168.0.0/24}。节点方面，集群创建 2 个 Worker 节点，节点规格为 \texttt{c9.large.2}，即 2 vCPU / 4 GiB，操作系统为 Ubuntu 22.04.5 LTS，容器运行时为 containerd。

\subsubsection{OBS数据存储配置}

OBS 在任务书中主要服务于 Spark 大数据分析方向，用于保存待分析数据集并通过 \texttt{s3a://} 接口供 Spark 作业读取。本项目的 \texttt{spark/analysis.py} 支持将数据路径作为参数传入，因此既可以读取仓库中的本地 \texttt{douban\_movies.csv}，也可以在云端 Spark 环境中替换为 OBS 路径。由于当前截图文件夹中没有单独保存 OBS 控制台截图，本章不虚构 OBS 页面证据；后续 Spark 大数据分析章节将围绕数据读取方式、SparkApplication 配置和实际分析结果继续说明。

从架构角度看，OBS 与 CCE 的关系并不是直接部署关系，而是作为 Spark 作业的数据源存在。Spark Driver 和 Executor 在运行时通过 S3A 协议访问对象存储中的数据文件，完成 DataFrame 加载、清洗和 SQL 分析。该设计将计算资源和数据存储解耦，符合云计算环境中“存算分离”的基本思想。

\subsubsection{ELB负载均衡配置}

\subsubsection{命名空间与资源规划}

本项目基础任务主要使用 Kubernetes 的 \texttt{default} 命名空间，便于课程设计验收时统一查看 Pod、Deployment、Service、ConfigMap、Secret、PVC 和 HPA 等资源。后端 Deployment 命名为 \texttt{backend}，Redis Deployment 命名为 \texttt{redis}，前端 Deployment 命名为 \texttt{frontend}；后端 Service 命名为 \texttt{backend-svc}，Redis Service 命名为 \texttt{redis-svc}，前端 Service 命名为 \texttt{frontend-svc}。配置资源方面，后端使用 \texttt{backend-config} 注入 Redis 地址和端口，使用 \texttt{redis-secret} 保存 Redis 密码字段；持久化存储方面，Redis 使用 \texttt{redis-data-pvc} 申请云硬盘存储。

资源规划遵循以下原则：第一，业务资源命名与任务书中的组件名称保持一致，便于截图识别和答辩说明；第二，敏感配置与非敏感配置分离，分别放入 Secret 和 ConfigMap；第三，对外访问只通过后端 LoadBalancer Service 暴露，Redis 保持 ClusterIP 内部访问，降低不必要的公网暴露风险；第四，后续 Spark Operator 或监控系统如需单独命名空间，将在对应章节中说明。本章环境配置完成后，后续章节即可在该 Kubernetes 集群之上继续完成应用部署、持久化、配置挂载、弹性伸缩和 Spark 大数据分析任务。
