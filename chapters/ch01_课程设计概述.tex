\section{课程设计概述}
\subsection{设计目标与任务要求}

本课程设计按任务书要求分为两部分：前半部分完成云平台上的 Web 应用部署，后半部分完成 Spark 大数据分析。实际操作时，我们在华为云 CCE 中创建 Kubernetes 集群，把后端、前端和 Redis 做成镜像后部署到集群中，并继续完成持久化存储、配置挂载、弹性伸缩等验证。Spark 部分通过 Spark Operator 提交作业，记录数据清洗、统计查询和性能对比结果。

任务书中，云计算平台搭建部分占 50 分，要求部署“Flask 后端 API + Redis 数据库”两层 Web 应用，覆盖容器化、CCE 集群、Kubernetes 应用部署、Redis 持久化、ConfigMap Volume 挂载和 HPA。并行编程实战部分占 40 分，需要在前面搭好的 Kubernetes 平台上选择 Spark 或 MPI 方向继续完成实验。我们选择方向 A，也就是 Spark 大数据分析，主要完成数据清洗、Spark SQL 统计分析、Pandas 与 PySpark 性能对比，以及 Amdahl 定律分析。剩下 10 分为报告质量，主要看结构、截图、图表和结果分析是否完整。

\subsubsection{总体设计目标}

我们的目标比较明确：Web 应用要能通过公网入口访问，Redis 数据在 Pod 重建后不能丢失，配置文件和密钥要由 Kubernetes 资源管理，后端还要能根据负载自动扩缩容。Spark 部分需要在同一个 CCE 集群中提交 PySpark 作业，并给出 Driver、Executor、运行日志和分析结果。

图 \ref{fig:overall-architecture} 是本项目的总体架构。在线应用部分以 ELB 和 \verb|backend-svc| 作为入口，请求先到 Service，再转发到两个 Flask 后端副本；后端通过集群内部的 \verb|redis-svc| 访问 Redis，Redis 的数据目录挂载到 PVC 上。前端由 Nginx 提供静态页面和反向代理配置，ConfigMap 用来挂载配置，Secret 保存 Redis 密码，HPA 用来观察后端副本的扩缩容。离线分析部分由 Spark Operator 提交 SparkApplication，在 CCE 集群中创建 Driver 和 Executor，运行 PySpark 脚本后输出清洗、查询和性能测试结果。

\reportfig[\textwidth]{figures/course-architecture.png}{课程设计总体架构与关键数据流}{fig:overall-architecture}

实现时，我们先改 Dockerfile 和应用配置，在本地用 Docker Compose 联调，再把镜像推送到 SWR。云端部署阶段需要用 kubectl 反复检查节点、Pod、Service、PVC 和 HPA 的状态。Spark 部分除了提交作业，还要看 Driver 日志、Executor 数量、CSV 输出和图表结果，最后再解释为什么小数据集下 Pandas 反而比 PySpark 更快。

\subsubsection{云计算平台搭建任务要求}

云计算平台搭建部分包括 T1 至 T6。T1 要求完成应用容器化：后端 Dockerfile 需保留多阶段构建结构，并在依赖文件中加入至少一个自选 Python 包；前端 Nginx 默认首页需包含本人学号和姓名；本地需通过 Docker Compose 验证后端与 Redis 通信正常，并将后端、前端镜像推送到 SWR，保留镜像名称和 Tag 的控制台截图。T2 要求通过 CCE 控制台创建 Kubernetes 集群，集群版本不低于 1.27，至少包含两个 Worker 节点，并通过 \verb|kubectl get nodes -o wide| 证明节点处于 Ready 状态且输出中包含 VERSION 列。

T3 要求将任务 1 形成的镜像部署到 CCE 集群。后端 Deployment 需设置两个副本，配置资源请求与限制，并通过 ConfigMap 注入 Redis 地址、通过 Secret 注入 Redis 密码；Redis Deployment 设置一个副本，并通过 ClusterIP Service 仅在集群内部访问；后端 Service 使用 LoadBalancer 类型并绑定华为云 ELB，使外部能够访问 \verb|/api/ping| 并获得正常 JSON 响应。T4 要求为 Redis 配置 PVC，并通过“写入数据、删除 Pod、重建后查询”的过程证明数据未丢失。T5 要求将 Nginx 反向代理配置以 ConfigMap Volume 形式挂载到前端 Pod，并通过进入 Pod 查看配置文件证明更新生效。T6 要求为后端配置 HPA，通过压测观察副本扩容与停止压测后的缩容过程，并分析扩容延迟、冷却时间和弹性伸缩的成本价值。

\subsubsection{并行编程实战任务要求}

并行编程部分我们选择方向 A：Spark 大数据分析。第一步是在 CCE 集群中安装 Spark Operator，并把 SparkApplication 模板改成实际可用的镜像地址、Executor 数量和内存参数。环境是否成功，主要看 WordCount 作业能否跑完，以及 Driver Pod、Executor Pod 是否进入 Completed 状态。后续分析使用豆瓣电影评分数据集，PySpark 脚本会先输出 Schema、前 5 行样例、字段缺失比例和清洗前后行数；缺失值字段至少采用两种处理方式，便于比较清洗前后的变化。

统计查询部分需要覆盖四类操作：GROUP BY 聚合、ORDER BY Top-N、时间趋势分析，以及 JOIN 或窗口函数。每个查询都保留结果截图，并写出我们从结果中能看到什么。性能对比则从这些查询中选一个代表性任务，分别用 Pandas、PySpark 单 Executor 和 PySpark 双 Executor 运行，记录耗时后画图比较。最后再结合 Amdahl 定律分析为什么实测结果没有达到线性加速，重点看 Spark 启动、任务调度、通信、序列化和数据量这些因素。

\subsubsection{提交材料要求}

最终提交内容包括 PDF 实验报告和代码仓库链接。PDF 中需要能看清 Pod 状态、节点版本、镜像 Tag、接口返回值、PVC Bound 状态、ConfigMap 更新结果和性能数据。代码仓库中保留后端、前端、Kubernetes YAML、Spark 脚本、Dockerfile 和主要截图，便于核对实验过程。

\subsection{小组分工与完成情况}

本课程设计由李欣纯和郑瑞璟共同完成。整体分工遵循“云平台实施”和“应用开发、数据分析及报告整合”并行推进的原则：一方面，郑瑞璟集中负责 CCE、Kubernetes、PVC、ConfigMap Volume、HPA、Spark Operator、监控系统以及附加题云端运行验证等真实云资源相关工作，降低多人交叉修改集群配置造成的不一致风险；另一方面，李欣纯负责应用容器化、镜像构建、Spark 数据清洗、SQL 分析、性能对比、PyTorch DDP 代码实现和报告主笔，郑瑞璟也参与报告中云端实验材料核对、问题记录补充和文字优化，从而保证代码、实验数据和文字材料能够统一整理。两位成员最终工作量按项目实施难度、排错成本、截图整理和报告撰写综合计算，约为 1:1。

\subsubsection{代码仓库与报告材料说明}

代码和实验材料统一保存在课程设计仓库中。仓库根目录包含 `backend`、`frontend`、`k8s`、`spark`、`figures`、`figures\_A` 等目录，分别用于保存后端应用、前端静态页面、Kubernetes 资源文件、Spark 分析脚本和实验截图。后端部分以 Flask 提供 `/api/ping` 接口，并通过 Redis 验证服务间通信；前端部分基于 Nginx 提供静态页面和反向代理配置；`k8s` 目录保存 Deployment、Service、ConfigMap、Secret、PVC、HPA 等 YAML 文件；`spark` 目录保存 WordCount 示例、SparkApplication 模板和豆瓣电影数据分析脚本。

报告截图主要来自 `figures` 和 `figures\_A` 目录。`figures/T1` 保存应用容器化、本地联调和 SWR 镜像推送相关截图；`figures\_A/T2` 至 `figures\_A/T5` 保存 CCE 集群、应用部署、Redis 持久化和 ConfigMap Volume 挂载相关截图。截图中保留了 Pod 状态、Service 类型、ELB 公网 IP、PVC Bound 状态、Redis 数据持久化结果以及接口返回值等信息，答辩时可以直接对照代码和配置文件查看。
