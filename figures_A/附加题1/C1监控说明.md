## 4. Prometheus Pull 采集原理

Prometheus 采用 Pull 模式采集指标。Prometheus Server 按照配置中的抓取任务和服务发现结果，周期性向各个 Exporter 或应用暴露的 `/metrics` 接口发起 HTTP 请求。被监控组件只负责暴露当前指标数据，Prometheus 主动拉取这些数据并写入本地时序数据库。

在 Kubernetes 集群中，Prometheus 通常配合 Prometheus Operator、ServiceMonitor、PodMonitor 和 Kubernetes 服务发现机制使用。`node-exporter` 负责暴露节点 CPU、内存、磁盘、网络等基础指标；`kube-state-metrics` 负责暴露 Deployment、Pod、PVC、Service 等 Kubernetes 资源状态指标；业务应用如果暴露 `/metrics`，也可以被 Prometheus 纳入采集范围。Pull 模式的优点是采集入口统一、目标状态可观测、便于发现采集失败的 Target，也适合在 Kubernetes 中动态发现新增或删除的监控对象。

## 5. 关键指标含义

- CPU 使用率：表示节点或工作负载当前实际消耗的 CPU 资源占其可用或限制资源的比例。CPU 使用率越高，说明计算资源压力越大，可用于判断是否需要扩容或优化应用逻辑。
- 内存使用率：表示节点或工作负载当前已使用内存占可用或限制内存的比例。内存使用率持续升高可能表示缓存增长、内存泄漏或资源限制设置过低。
- CPU 分配率：表示已被 Pod request/limit 等资源配置占用的 CPU 资源占集群总 CPU 资源的比例，用于判断集群资源是否已经被过度申请。
- 内存分配率：表示已被 Pod request/limit 等资源配置占用的内存资源占集群总内存资源的比例，用于判断集群是否仍有足够空间承载新的工作负载。
- 网络上下行速率：表示工作负载在单位时间内接收和发送的数据量，可用于分析业务访问量、接口调用频率或异常流量。
