# A-0 Spark Operator 环境部署说明

## 1. 任务目标

A-0 的目标是在华为云 CCE 集群中部署 Spark Operator，并通过 SparkApplication 提交 PySpark WordCount 示例作业，验证 Spark Driver Pod 和 Executor Pod 能够在 Kubernetes 中正常创建、运行并完成。

## 2. Spark Operator 部署

初始安装 Spark Operator 后，`spark-operator-controller` 和 `spark-operator-webhook` Pod 出现镜像拉取失败。排查发现默认镜像地址为 `ghcr.io/kubeflow/spark-operator/controller:2.5.0`，在当前云环境中无法稳定拉取。

处理方式如下：

- 将 Spark Operator 镜像推送到成员 A 的华为云 SWR 组织 `cloud-course-a`。
- 将两个 Deployment 的镜像切换为 `swr.cn-north-4.myhuaweicloud.com/cloud-course-a/spark-operator-controller:2.5.0`。
- 将 default 命名空间中的 `default-secret` 复制到 `spark-operator` 命名空间。
- 为 `spark-operator-controller` 和 `spark-operator-webhook` Deployment 绑定 `imagePullSecrets`。

最终执行 `kubectl get pods -n spark-operator`，两个 Operator Pod 均为 `1/1 Running`。

## 3. SparkApplication 配置

最终用于 A-0 的 SparkApplication 关键参数如下：

```yaml
image: swr.cn-north-4.myhuaweicloud.com/xinchunli/pyspark:3.5.4-a3
mainApplicationFile: local:///opt/spark/work/wordcount.py
sparkVersion: "3.5.4"
driver:
  memory: "1g"
executor:
  instances: 2
  memory: "1g"
```

由于 PySpark 镜像位于成员 B 的 SWR 组织 `xinchunli`，在 default 命名空间中创建了 `b-swr-secret`，并将其绑定到 Spark 使用的 `spark` ServiceAccount。

## 4. 问题与解决

实验过程中主要遇到以下问题：

- 默认 Spark Operator 镜像拉取失败：通过改用成员 A 的 SWR 镜像解决。
- PySpark 镜像缺少 `wordcount.py`：成员 B 重新推送镜像，确认镜像内包含 `/opt/spark/work/wordcount.py`。
- Driver 内存配置为 `256m` 时启动失败：日志显示 `INVALID_DRIVER_MEMORY`，Spark 要求系统内存至少约 450 MiB，因此恢复为 `1g`。
- 原有两个 `c9.large.2` 节点资源不足：Executor Pod 出现 `Insufficient memory`，因此新增 2 个 `c9.large.4` Worker 节点。

新增节点后，WordCount 作业成功创建 1 个 Driver Pod 和 2 个 Executor Pod，最终全部进入 `Completed` 状态。
